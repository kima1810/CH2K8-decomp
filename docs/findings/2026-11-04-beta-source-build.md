# Beta distribution and XEX/ISO source builds

Tester screenshots showed a source checkout without `port/out/build/.../ch2k8.exe` and an older ISO worker invoking the Windows Store Python alias. The source archive is not a compiled release. The updated launcher identifies this case, links to a runnable beta release asset, offers direct XEX selection for extracted discs, and provides a source-build button for full checkouts.

`tools/build_ch2k8.ps1` accepts the supported USA XEX, an extracted folder or ISO. It detects a functioning Python 3.11+ interpreter by probing explicit paths, the project environment, `py -3`, PATH, registry entries and installation folders. Microsoft Store aliases are skipped. Source builds refresh the standalone native helper, validate the XEX identity, stage a private default.xex for code generation, prepare the pinned SDK if missing, generate/correct/optimize the guest code, configure Release and build the game and native tools. ISO builds additionally import loose assets; `-CodeOnly` explicitly omits that data step. Bare XEX builds still require game assets before play.

The new native `extract-xex` command reads a validated ISO without a full asset import when preparing the code-generation input. It refuses to overwrite an incompatible existing XEX. A regression test verifies input preservation and extraction/reuse behavior. The CMake Python path is normalized before embedding it into a generated command, avoiding Windows backslash escapes such as `\P`.

Source-build logs and the executable/game-data result are saved under userdata. The launcher can remember a custom source-build executable; portable installations prefer their local executable when copied or updated. Runtime ISO import and asset preparation still use native code and require no Python installation.

Validation includes a clean checkout with no generated sources, cold code generation and Release compilation from the retail XEX, followed by the retail ISO path. This was isolated from unrelated in-progress GPU-wait work in the original checkout. The runnable release preserves the last clean tracked game/runtime build and records its source revision separately from the updated launcher/native helper revision. Automated regressions exercise Python detection, alias rejection, unsupported-XEX refusal, native extraction, relocated launch/import and the existing native asset protocol. Hardware/gameplay coverage remains the beta matrix.
